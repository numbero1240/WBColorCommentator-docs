# 2026-10-06 カードのデータの登録（M7 の準備）

## 規約の確認
- カードの効果やイラストを「ゲーム内から」取得することについて、方法ごとに整理し直した
  - ゲームのファイル・メモリ・通信から抜き出す：禁止（第11条第1項第14号、第5条第3項の「人間が認識できる形式に変更」）
  - 自分の録画から画面に映ったカードを切り抜き、手元だけで使う：文字どおりに読むとグレーだが、個人的な利用の範囲で低リスク（今の方式）
  - 画面や公式サイトを見て、効果を独自の形式に手で書き起こす：低リスク
- 公式サイトのカード一覧の使い方を決めた
  - プログラムでの一括取得はしない（公式のデータを丸ごと複製することになり、第5条第3項に正面から当たる。
    robots.txt もこちらからの取得が拒否された）
  - 公式のカード画像は使わない（画像の複製になるうえ、ゲーム画面のカードと枠や縮尺が違い、見本として精度も出ない）
  - **利用者がブラウザで開いて効果の文章をコピーし、ツールに貼り付けると下書きができる方式**にした。
    ツール自身は公式サイトにアクセスせず、貼り付けた文章は保存しない。POLICY.md にも追記した

## やったこと
- Web UI に「カードのデータ」画面を追加した
  - 名前を付けたカードの一覧（未登録だけ／すべて）から選び、種類・コスト・攻撃力・体力・キーワード能力・効果を登録する（進化後の項目はあとで削除。下記）
  - コスト・攻撃力・体力は、取り込んだ試合で最も多く見た値を初期値にする（手札のコスト、場の攻撃力と体力）
  - 効果の文章を貼り付けて「解析」を押すと、【ファンファーレ】などの区切りと文の形から効果のデータの下書きを作る。
    読み取れなかった文は一覧にして、「未分類の効果」として追加し、自分の言葉でメモを付けられる
- 保存先は `data/cards/cards.yaml`（Git では管理しない）。「名前（進化）」のカードは元の名前のデータを使う
- Web UI の待ち受けの番号を 8765 から 18765 に変えた。8765 を Windows の HTTP.sys が使っていて、
  ブラウザで開くと Windows 側が「Bad Request」を返していたため

## 解析できる文の形
ダメージ（リーダー、選んだフォロワー、すべて、ランダム）、破壊（選ぶ、ランダム、すべて）、回復、ドロー、
場に出す（『』で囲まれたカード）、PP 最大値 +N、強化（これ、自分の場のすべて、他のすべて）、手札に戻す。
キーワード能力：守護、疾走、突進、必殺、ドレイン、威圧、潜伏、オーラ、バリア。
テストには実在のカードの文章ではなく、同じ書き方の例文を使った。

## 用語の見直し（公式の「バトル Tips」で確認）
カードのデータの登録画面の選択肢は、最初は前作の知識と録画に映った文章から決めていた。利用者が公式のカードページの
「バトル Tips」（用語の説明）を開いてくれたので、それを 1 ページ読んで確かめた（説明文は保存していない）。
- キーワード能力の 9 つ（守護、疾走、突進、必殺、潜伏、ドレイン、威圧、オーラ、バリア）はすべて実在した
- カードの種類に「クレスト」を追加した
- 効果の内容に「手札に加える」「消滅」「捨てる」「変身させる」「デッキに戻す」を追加し、解析できる文の形も増やした
- 発動に「スペルブースト時」を追加した。コンボ、覚醒、ネクロマンス、エンハンス、連携、奥義、カウントダウンなどの
  条件の区切りは「条件など」として区切りの名前を入れられるようにし、入力候補に出すようにした（以前は画面に出ていなかった）
- ルールの裏付け：場は 5 枚まで、手札は 9 枚まで、PP の上限は 10、EP・SEP は 2 つずつ、進化・超進化の効果と使えるターンは実装どおり
- 今後に関わる点：潜伏・威圧を持つフォロワーは相手のフォロワーから攻撃されず、守護と同時に持つと守護は無効になる。
  必殺は攻撃力 0 でも働く。最善手の計算でキーワード能力を使うときに反映する

## 作業中の内容を残す

- 貼り付けた効果の文章と保存前の下書きを、カードごとに残すようにした。別のカードや別の画面に移っても、ページを再読み込みしても消えない
- 置き場所はブラウザのそのタブの中（sessionStorage）だけで、ツールのデータとしては保存しない。
  「保存」「削除」「作業中の内容を捨てる」を押すか、タブを閉じると消える。一覧には「作業中」と表示する。POLICY.md にも追記した
